<p>很多人把「家宽 IP」当成一件商品去买，其实它是四层东西叠起来的：线路本身的归属、出口的粘性、浏览器里的环境、以及这批号怎么编排。任何一层松了，客户演示那天都可能卡在登录页。下面按层拆开讲，每层给一个能当场验证的判据，不靠感觉判断。</p>
<h2>一、把「家宽出口」拆成四层再谈选型</h2>
<p>分层的好处很实在：出了问题能定位到具体哪一层，而不是笼统说一句「IP 不稳」然后换一家供应商重来。四层从下往上分别是物理层、会话层、应用层、运营层，越往下越难改，越往上越容易被忽略。</p>

<h3>为什么不该一上来就换供应商</h3>
<p>换供应商只动了物理层，另外三层原样保留。如果问题其实出在应用层——比如两个号一直共用一份浏览器配置——换十家线路也照样串。先按层自检一遍，能省掉大部分试错成本。</p>
<h3>四层的修改成本差多少</h3>
<p>运营层改一张表就完事，应用层改一个配置目录，会话层调一个粘性参数，物理层要重新采购并等交付。顺序做反了，等于用最贵的手段去解决最便宜的问题。</p>
<h2>二、物理层：归属地和实际落地地区必须对得上</h2>
<p>「同一批号固定走同一出口地区」这句话落到执行上就是两件事：这条线注册在哪个国家，以及流量实际从哪个城市出。两者不一致时，页面照样能打开，但地区相关的展示会露出破绽，比如货币单位、可用功能、推荐内容全都不对。</p>
<h3>三步验证归属</h3>
<p>第一步用 whois 或 RDAP 查 IP 段的注册机构与分配日期；第二步查 ASN，看持有者是不是本地宽带运营商，家宽段通常挂在小 ISP 或地区性运营商名下，而不是大型云厂商；第三步用两三家 IP 库交叉核对城市，如果三家给的州都不一样，这条线就别用在需要地区一致性的场景里。</p>
<h3>按国家锁还是按城市锁</h3>
<p>只做对话和订阅，按国家锁足够；要用到本地生活类功能、当地货币计价，或者客户本身就在某个都会区，建议锁到城市并顺带核对时区。城市级锁定对供应商的要求更高，采购前先问清楚能不能指定，别等开通了才发现只能选国家。</p>
<h2>三、会话层：出口粘性别被「自动轮换」坑了</h2>
<p>不少套餐默认开着自动轮换，每隔几分钟换一次出口。这种设计适合抓公开数据，不适合带登录态的场景。账号在会话中途换 IP，轻则要求重新验证，重则直接退出，演示时最怕这个。</p>
<h3>粘性时长怎么定</h3>
<p>原则只有一条：粘性窗口要长于单次会话本身。日常对话按三十分钟设，长文档处理和一小时以上的演示按两小时设，跨天的常驻任务用固定出口而不是粘性会话。参数名各家不同，常见叫 session、sticky、ttl，开通时请对方把具体数值写进工单，口头承诺不算。</p>
<h3>重连之后要做的比对</h3>
<p>脚本里记两个字段：会话 ID 和出口 IP。断线重连后先比对 IP 是否与前一次相同，不同就写一条告警日志，不要静默继续跑。这条日志在排查「客户说演示时页面刷新了」这类问题时特别有用，能直接把责任落到线路侧。</p>

<h2>四、应用层：一号一环境最容易串的三样东西</h2>
<h3>Cookie 与本地存储</h3>
<p>同一份配置目录下，Cookie 和 localStorage 是共享的。判断方法很直接：看配置目录路径是否相同，相同就是共用。给每个号建独立目录，目录名用账号编号，别用「测试1」这种容易重名的命名。</p>
<h3>指纹里的时区与语言</h3>
<p>出口在洛杉矶，浏览器时区却是北京时间、语言是简体中文，这种组合本身就矛盾。环境里把时区、语言、地理位置权限一起对齐到出口所在地，比只改 UA 有效得多。三处对齐之后，同一批号的资料看起来才像一个人在用。</p>
<h3>扩展与账号同步</h3>
<p>浏览器账号同步会把书签、扩展甚至部分登录态带到新环境里。演示用的配置文件一律关闭同步，扩展只留必需的，多余的先禁用，需要用的时候再一个个开回来。</p>
<h2>五、运营层：批次编排与演示当天的预案</h2>
<p>同一批号固定走同一出口地区，本质是运营纪律。批次一旦定下来，出口地区、环境目录、负责人三项就绑在一起，后续只允许整体替换，不允许单号悄悄漂移。</p>

<h3>批次怎么分组</h3>
<p>按客户或按项目分组，同一组内共用出口地区，组与组之间用不同城市。这样某条线出问题时影响面被限制在一个组里，不至于整批陪跑。分组表放在共享文档里，谁改了哪条线写一行记录。</p>
<h3>演示当天的最小预案</h3>
<p>准备两个号、两条不同线路。主用号提前两小时登录保持会话，备用号只在主用号出问题时启用。演示机关闭系统自动更新和自动休眠，插上电源，避免中途黑屏把会话打断。这套安排不复杂，但能把大部分现场事故挡在门外。</p>
<h2>常见问答</h2>
<h3>同一批号必须走同一个城市吗？</h3>
<p>答：不是必须，但推荐。同一城市能让账号资料、时区、语言三处保持一致，减少解释成本。如果客户分布在多个城市，按客户分组，组内统一就够了。</p>
<h3>家宽线路延迟比机房高，会影响演示吗？</h3>
<p>答：日常对话基本感觉不出来，多出的一两百毫秒通常被模型生成时间盖住。真正影响体验的是会话中断，所以粘性参数比延迟更值得关注。</p>
<h3>怎么判断这条线是不是真的家宽？</h3>
<p>答：看 ASN 持有者是否为本地 ISP，再看 IP 段的历史用途记录。也可以观察同段邻居的开放端口情况做辅助判断，端口全开的多半是机房段。</p>
<h3>粘性会话会不会更容易被识别成固定出口？</h3>
<p>答：真实家庭宽带本身就是长期不变的出口，固定反而更符合常态。前提是一个号对一条线，多个号挤一条线才是问题所在。</p>
